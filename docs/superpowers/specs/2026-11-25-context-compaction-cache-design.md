# 自动压缩和缓存前缀设计

共享 Rust AgentSession 负责所有入口。/compact 在提交入口拦截，恢复历史后执行主动压缩，不作为用户任务发给模型。

自动触发使用输入 token 压力和历史序列化大小两项。预算预留输出空间及安全余量，取消固定消息条数触发。历史内存保护使用 512 KiB 内部上限，近期历史目标不超过 128 KiB 对应的保守 token 预算。模型窗口配置保留，未知自定义模型继续使用保守默认窗口。

压缩选择完整旧消息段，近期完整工具调用组保留。仅摘要被移除的前缀，避免重复摘要近期消息。无可移除段时跳过。摘要输入通过已有有界转换限制，失败使用本地摘要。摘要保留目标、约束、路径、关键工具证据、失败和下一步。压缩不能解决单个超大消息，后续应完善工具源头限流。

配置移除 trigger_message_limit、recent_message_limit、summary_max_chars、model_compact 的外部读取与示例，内部策略自动管理。模型窗口和输出上限作为必要模型能力信息保留。

缓存改进：时间在用户消息入历史时固定，后续工具轮次不重写；稳定 Memory 和技能目录位于摘要之前；接入 DeepSeek cache hit 指标。后续动态快照协议需单独验证语义，本次沿用现有 Memory 刷新行为。

验证使用 Rust 现有测试、格式检查和编译。内存阈值是工作集保护，不代表进程 RSS 硬上限，真机峰值需连接设备后测量。

## 实现细化

保留区使用连续后缀并在用户轮次边界切分，以借用切片和 split_off 移动历史，避免克隆整份消息。主动压缩至少保留最新用户轮次；无旧轮次时明确反馈无需压缩。压力过高时允许收缩到最新轮次，单个无法容纳的轮次返回明确错误。压缩前后记录估算量、字节数及保留范围。

摘要输入的工具证据使用有界文本，整体上限 24 KiB，摘要上限 12000 字符；模型摘要输出不超过 2048 tokens。摘要模型失败则使用本地有界回退。四个旧压缩配置字段从配置结构及展示中删除，测试改为验证自动策略。

## 模型能力层（0.1.69）

模型配置 input_context_tokens 默认 0 表示自动，不再表示关闭 token 压缩。能力解析放在模型层，按 provider、API 主机及精确模型 ID 解析。已核验的官方 DeepSeek Flash/V4 Pro、OpenAI GPT-4.1/4o/5/5.2 使用内置窗口及输出上限，未知服务或自定义别名回退 48000 token，避免把官方模型容量套用到第三方部署。自定义窗口覆盖仍可选，已知模型覆盖不能超过已知容量。

压缩预算取窗口 80% 与扣除有效输出预留和安全余量后的预算较小值。实际模型请求也使用同一个有效输出上限。原有 512 KiB 历史触发、768 KiB 单轮保护继续生效。诊断显示解析后的窗口、输出限制及来源。

掌机设置切换 API 地址、provider 或模型 ID 时清除旧窗口覆盖，保存同一模型或仅更新密钥时保留覆盖。当前掌机的历史手填窗口在部署时移除，改为自动解析。切换后每次请求根据当前配置重新解析，避免跨模型沿用容量。

## 可选上下文内存预算（最新需求）

常规压缩由当前模型上下文预算触发。删除固定 512 KiB 触发与 768 KiB 拒绝阈值。新增可选 session.max_context_memory_mib，默认 None，配置省略或 0 表示不额外限制；正整数表示上下文内容的 MiB 预算。此预算统计消息正文、工具参数、摘要、Memory、技能目录与工具定义，属于模型上下文内容估算，不是进程 RSS 硬限制。

设置该预算时，在构造历史副本前检查，超预算先尝试压缩旧完整轮次。无法缩减到预算内则返回容量错误，避免继续构造模型请求。菜单历史设置提供 MiB 输入，0 清除 TOML 中该配置。掌机本次部署保持默认未配置，不再沿用“暂设10MiB”的早期选择。示例仅注释展示可选值10。

验证包含默认超过旧阈值不压缩、显式预算触发压缩、单轮超预算拒绝、配置值校验、菜单保存及清除，以及模型 token 触发回归。

## DeepSeek Harness 在线能力生命周期对照（源码复核）

依据 2026-11-25 获取的 master 源码，前述“实际压缩容量仍只来自静态配置”的判断不完整。官方 API-key 路由的 connect 会先调用 listings.view，connectionOf 将 resolveListedCatalog 得到的 catalog.resolution 放入 connection.models；prepareCall 捕获该 connection 后再调用 modelInfo，在线容量因此能进入当前请求的预算。只查看 model-info.ts 会漏掉调用前的合并过程。

- 首次访问端点与凭据对应的缓存作用域时等待查询，默认整个查询超时 5000ms。访问可以由模型发现，也可以由请求准备触发。
- 缓存默认600000ms（10分钟）有效。后续读取立即返回已有视图，过期时后台更新，并在首次使用后启动自动刷新计时器。
- 同一作用域正在进行的查询合并复用。作用域由查询URL和实际认证头SHA-256组成。作用域变化时取消旧请求，generation阻止旧结果覆盖新作用域。
- 查询失败保留最近成功结果，没有成功结果时回退内置目录。失败按相同刷新间隔再试，连续失败仅首条告警，不能描述成指数退避。
- 每次prepareCall捕获连接快照，当前请求保持一致。更新的容量可进入下一次模型请求，不是固定等到下一轮用户消息。
- 该缓存实现是进程内缓存，源码未实现磁盘持久化。Colibri若增加跨进程磁盘共享缓存，应明确作为轻量终端的额外设计。
- 在线跟随存在适用条件：官方API-key路由在官方端点、内置模型目录未被显式自定义时启用。其他厂商是否发现和采用容量由各自适配器决定。

拟修正Colibri在线设计：采用首次使用有界等待、10分钟缓存、过期后台更新、同作用域请求合并、查询失败保留成功结果、每次模型请求固定能力快照。与掌机启动界面解耦，App启动读取历史不触发网络查询。尚未实现在线查询，部署版本仍使用内置表。

## 移除工具轮数配置与固定停止（最新需求）

删除 session.max_tool_rounds 配置及固定32轮停止逻辑。共享 Agent 循环继续执行模型与工具，直到模型返回最终答案、模型错误或现有用户退出/中断路径生效。不会把旧配置改成隐藏的固定轮数。删除只服务于轮数停止的摘要辅助逻辑，旧键按未知字段拒绝，部署时仅移除掌机该键。

input_context_tokens 是模型输入与输出的 token 容量覆盖，默认自动识别；max_context_memory_mib 是可选的本机上下文内容大小预算，默认省略。前者限制模型请求容量，后者限制估算的上下文内容，不能当作进程RSS限制。两种压力独立触发压缩。

验证使用会执行40次工具调用后自然结束的模型，确认跨过旧32轮边界；保留模型错误和压缩回归。历史 Python 对照中的轮数限制属于有意行为分歧，测试覆盖映射改为相应新行为。

## 统一交付：在线能力缓存与用户配置隔离

在线 context_window/context_length 和 max_output_tokens/max_completion_tokens 仅进入独立缓存与每次请求的能力快照，绝不写入 config.toml、菜单字段或 Launcher 配置。用户主动设置的覆盖值仍留在 config.toml。来源优先级为手动覆盖（受服务实报容量约束）、在线/成功缓存、内置目录、保守默认。

首次准备真实模型请求时最多等待5秒，App初始化、读取历史、打开设置均不查询。缓存10分钟；过期请求立即使用最近成功值并启动后台刷新。为控制掌机耗电，空闲时不设置周期网络轮询，后续活动请求触发到期刷新。API地址、模型ID和凭据SHA256构成缓存键；仅缓存选中模型的必要数字元数据。每进程最多32个缓存槽、最多2个查询任务，响应上限1MiB，磁盘条目有界，禁止HTTP重定向。进程内合并重复查询，磁盘原子写入，跨进程复用最近成功结果。失效或失败保留成功值，失败后10分钟再尝试。

请求准备时由模型适配器获取能力快照，实际生成参数、压缩阈值、摘要调用均使用同一份快照。每个工具轮次可取得刷新后的新快照，进行中的模型请求保持不变。记录实际窗口和来源用于诊断，缓存中不存密钥和对话。持久缓存位于 Colibri home 下 cache/model-capabilities，具有0600文件权限。未知或无容量字段的模型不猜测在线容量。

同批验证此前压缩、/compact、固定时间戳、DeepSeek缓存统计、可选上下文内存预算默认None、移除工具轮数限制。部署统一版本0.1.72，清理旧max_tool_rounds，确认在线元数据不会改变用户配置。
