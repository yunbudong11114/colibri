# Colibri for Cardputer Zero

商店与启动器显示名统一为小写 `colibri`，命令为 `colibri`，Debian 包名保留 `colibri-cardputer` 以支持原地升级。设备版位于 `cardputer-zero/`，拥有独立的构建和启动器入口，复用 Colibri Rust 的模型、会话、上下文压缩和 transcript。现有 CLI、网关、权限库及配置默认值保持原入口行为。

## 平台

- 以官方 CardputerZero Template 和 AppBuilder 为基线。C++17 + LVGL 9.5，桌面 SDL2，设备 Linux framebuffer / evdev，CMake 生成 ARM64 Debian 包。使用 APPLaunch 的 desktop 文件布局。
- 320×170 界面采用标题、可滚动正文、输入行和底部快捷键。聊天消息用独立的说话者色签与正文分行，区分我、Colibri 和系统，无需解析正文标记。聊天、设置均可通过键盘操作。菜单和设置列表直接用实体键 F/X/Z/C 选择、返回及打开。聊天及设置编辑保留这些字母的输入语义。语音只从聊天页快捷键启动。设备映射实际 Fn 按住事件，桌面用 Alt+Space 模拟。聊天面板的键盘滚动受内容边界约束，禁用弹性越界。聊天页使用 Fn+N 立即跳到最新消息，桌面模拟器使用 End。快捷键不提交或清空输入草稿。LVGL 只在 UI 线程更新。Rust worker 经本地管道交换 JSON 行，网络和录音在 worker 处理。
- 拼音输入支持单字候选选取、翻页和逐字组成句子。使用 FreeType CJK 字体。聊天界面直接用 Fn+Space 开始或结束录音，Esc 取消，录音最多 60 秒。设备默认从系统 PipeWire 的板载 ES8389 麦克风输入取 16 kHz 双声道 PCM，等收到音频帧才显示录音中，保留实际有语音信号的左声道并做有限增益，再交给识别器。ALSA 仍可显式选择。结束后转写到草稿，按 Enter 才发送。语音模式默认自动检测离线资源，可显式切换离线或在线 API；选用离线时录音不会发往网络。REPL 用 /voice 开始录音，按 Enter 结束。
- Cardputer Zero 的离线包仅装一套 Sherpa-NCNN 小型中英双语 Zipformer，使用两线程和贪心解码。打包 ARM64 原生运行时、模型和词表。GUI 与 REPL 共用转写流程。引擎需要一套完整的 ncnn 资源，已有外置 Sherpa-ONNX 中文包仍可由资源目录显式选用。中文存储目的地中的「纳斯」可规范为「NAS」，其它上下文保留原转写。转写结果可编辑，单独念缩写的准确率以真机验收为准。

## 会话和设置

- 主菜单一屏显示 MCP 与技能、设置、退出，沿用单活动会话设计，Esc/Z 返回聊天。MCP 与技能提供只读列表和名称说明页，查看时只使用本地配置与技能元数据，不连接服务器或执行命令。MCP 配置留在设置中；未提供说明时展示传输类型。明暗主题归入设置的显示菜单。

- 数据根目录使用核心的 `COLIBRI_HOME`，默认 `~/.colibri/`。设备版在该目录内写入 `settings.json`，历史同原版放在 `transcripts/`；原版 `config.toml` 保持独立。首次启动把旧设备目录中的设置和 JSONL 历史复制到新目录，保留旧文件及新目录已有文件。`--home` 或 `COLIBRI_CARDPUTER_HOME` 显式覆盖目录时跳过自动迁移。

- 设置首页按模型、图片理解、语音、搜索、历史、记忆、MCP 配置、显示分组，进入分组再编辑。模型参考 ZClaw 的服务商选择流程，提供 OpenAI、DeepSeek、OpenRouter、Ollama 预设和自定义 OpenAI 兼容连接。连接表单统一展示 Base URL、API Key、模型 ID，最后一次性保存；返回放弃草稿。保留同一地址已保存的密钥，切换地址时须重新输入密钥或显式使用无鉴权。已保存的平面配置继续可用。应用打开时本地验证模型配置。配置缺失或无效时，聊天页直接显示设置入口说明，保留草稿直至配置完成；错误信息不显示密钥或底层错误类别。长期记忆与原版共用 MemoryContext 和目录默认值 ~/.colibri/memory，设备设置可开关并修改目录。启用后自动加载 SOUL.md、USER.md、MEMORY.md，并允许模型列举、读取、搜索和写入本机记忆；聊天历史继续独立。「设置 → 记忆」按核心文件和主题分类，先阅读再编辑。编辑支持游标、换行和拼音，明确保存后才原子写回；检测并提示文件已被外部修改。文件访问限制在所配置的记忆目录内，编辑单文件上限为 64 KiB。
- 退出时保持当前菜单画面直到进程结束，不切到聊天或刷新下一帧。

- 图形界面及 `colibri --repl` 共享设备版配置、历史和工具。REPL 提供 `/new`、`/voice`、`/quit`。
- 设置覆盖模型名、URL、密钥，录音转写接口和模型，搜索引擎、URL、密钥，历史启用、恢复、保留天数和容量。密钥遮盖显示，设置文件原子替换且仅用户可读写。录音文件临时保存并清理。提前停止 ALSA 录音后，根据实际采样数据重建 WAV 文件头，再交给离线引擎或在线 API。访问默认 OpenAI 地址前检查密钥，缺少时在录音前显示设置路径。转写使用 5 秒连接超时和 20 秒总时限，区分网络、认证和接口错误。
- 掌机 GUI 与 REPL 注册 Rust 版全部内置工具，包括文件、Shell、图片理解、长期记忆、Skill、搜索和硬件工具。工具直接以掌机普通应用用户运行，应用不读取授权记录、不检查读写级别，也不弹出执行确认。文件工具可以访问应用账号在 Linux 下有权限访问的路径。可从数据目录的 config.toml 使用 shell、vision、hardware 配置。硬件操作仍需对应的设备别名和系统设备权限。没有活动收发通道时，files.send 返回通道不可用。
- 已配置 MCP 服务器的 stdio 进程启动、发现、工具调用、资源和提示查询直接运行，无额外确认。REPL 提供 call_tool。Skill 命令直接执行其声明的程序。系统账号权限、服务认证、工具输入验证和执行超时继续生效。记忆写入仍拒绝符号链接。

- 「设置 → 图片理解」可编辑视觉模型名称、API 地址、密钥、超时和图片大小上限。已存在的 config.toml [vision] 按字段作为菜单初始值，菜单仅在 settings.json 保存用户显式编辑过的字段，优先于 TOML。清空模型、地址或密钥使该字段沿用聊天配置，密钥只显示是否已设置。保存后重新加载当前会话配置。

## 验收

验证现有测试、设备版保存和读回、拼音、模型回合、工具集一致性、MCP 协议互通、桌面模拟器与 ARM64 包；真机验证按键、麦克风和 APPLaunch 生命周期。启动器采用用户选定的 M3「振翅」薄荷绿像素蜂鸟图标（100×100），商店使用同款 256×256 图标。

语音验收比较同一批掌机录音中的 NAS、MCP、中英混说、无术语的普通中文与静音。记录冷启动转写时间和模型峰值内存。只部署一套通过对比的模型，验证应用入口之后删除掌机和构建机上的测试录音及其它候选文件。

参考 [硬件](https://docs.m5stack.com/zh_CN/CardputerZero)、[官方模板](https://github.com/CardputerZero/Template)、[AppBuilder](https://github.com/CardputerZero/AppBuilder)、[MCP Python SDK](https://py.sdk.modelcontextprotocol.io/v1/)。

## Rust 运行时迁移

- 保留 C++17/LVGL 前端与 JSON 行协议。新增 ARM64 Rust worker，GUI 和 `colibri --repl` 共享该入口。发布包不携带 Python 解释器、模块或 Python worker。
- 会话直接使用 Rust AgentSession、模型、工具、记忆、上下文压缩、缓存计量及历史加载器。掌机采用会话级直接执行模式和数据目录作为工具工作目录，Rust CLI 及网关维持已有策略。
- 沿用扁平 settings.json、TOML 补充配置、旧目录迁移、GUI 密钥遮盖和原子写入。保留打开会话后的消息与摘要。记忆编辑保留目录和符号链接检查、大小限制及修订冲突检测。
- Rust MCP 客户端支持 stdio 与 Streamable HTTP、初始化、分页发现、工具调用、资源和提示。仅掌机已配置的服务加入当前会话，诊断不输出凭据。网络连接和本地子进程有超时及生命周期管理。
- 沿用 PipeWire/ALSA、Fn+Space、录音草稿、Sherpa-NCNN 与在线兼容转写。程序退出时清理录音临时文件。拼音候选随 Rust worker 提供，释放包不依赖 Python 字典加载。
- 在桌面测试协议和状态，在 ARM64 安装前验证离线启动、配置兼容、工具、MCP 和语音，再在掌机上核验实际配置、历史、启动和 RSS。验收失败时保留设备已安装版本。
- `colibri auth weixin` 与 `colibri gateway {run,start,stop,restart,status}` 从设备命令进入原有 Rust 微信与网关实现，支持原生 `--config` 参数。网关使用 Rust 的 TOML（含微信会话和认证信息），GUI 的 settings.json 继续负责本机界面。安装和验收不自动启动、认证或发送微信消息。
- 本机 Rust worker 的文件工具可访问应用账号依 Linux 权限可访问的路径。Shell 不启用 Colibri 默认命令拒绝清单。硬件别名、操作系统权限和服务认证沿用现有约束。独立 Rust CLI 和微信网关保留自己的配置入口。
- GUI 首次读取模型状态时用同一个 Rust 历史加载器返回有界的已完成对话，页面按时间顺序渲染并滚动到最新消息。受「保存记录」和「启动恢复」设定约束，不额外发模型请求，不创建或重写历史文件。
- 聊天正文在现有 CJK 字体之后使用随包分发的 Noto Emoji 单色字形补充缺字。小屏幕按当前聊天主题着色。国旗的双区域字母序列显示为 `[CN]` 一类的地区代码。只转换界面显示，保留原消息、草稿和历史记录。
- 聊天正文通过 MD4C 解析 Markdown，再用 LVGL 原生文字控件排版。支持标题、强调、列表、引用、行内代码、代码块、链接文字和 GFM 表格。320×170 屏幕上的表格按行折成带表头标签的纵向条目。代码按字面显示并折行。链接仅显示标签，图片仅显示替代文字，渲染不读取网络资源。原始消息、历史与输入草稿保持不变。限制单条消息的渲染节点，超限时回退为纯文本。
- 聊天输入 `/clear` 后按 Enter，清空可见聊天消息和滚动位置，继续显示新消息。命令在界面处理，未配置模型时也可用，支持拼音模式直接录入。聊天记录与 Agent 上下文保持原样。菜单经 Esc 或左方向键返回聊天时，在布局更新后滚动到最新消息。
- Markdown 代码块在深色及浅色主题下使用独立底色和完整描边，与消息卡片及引用区分。代码文字继续使用正文前景色和等宽字体。
- 安装包文件名、AppBuilder 显示名及本地化标题、APPLaunch 启动器和应用页标题统一为 Colibri。Debian 包标识、命令、文件路径继续使用现有小写命名，保留原地升级和已有调用。
- 中文输入在聊天和记忆编辑里支持离线连续全拼。Rust worker 以带频率的简体中文词库和单字表对最多 64 字节的全拼进行切分和排序，优先显示整段候选，保留可单独提交的前缀候选。单引号可明确分隔音节。界面按实际文字宽度分页显示多字候选，沿用空格、数字选词、方向键翻页、退格和 Esc。选中部分候选时保留剩余拼音。已有单字协议继续可用，英文混输沿用 Tab 切换。验收覆盖常用词、完整中文句子、部分上屏和中英文混输，所有查询在设备本地完成。
- 深浅主题沿用 Colibri 的薄荷绿主色，代码块使用同一色系的蓝灰底和描边，引用使用更醒目的绿色竖线，列表选中行使用薄荷绿圆角底和高对比文字。按统一的留白、圆角和字号布局。代码块按实际字宽填满当前显示行后折行，保留原始换行及空格，避免长标识符把开头字段单独挤到一行。菜单使用固定四行，长标签显示省略号，选中态随现有键盘操作移动。
- 启动检查模型和恢复历史期间，聊天正文保持空白，状态栏显示检查进度。收到模型状态及历史后一次性绘制结果，仅在模型可用且没有可见消息时显示空会话提示。初始化失败直接显示错误。
- 掌机聊天的 `/clear` 保存独立的界面历史边界。Rust worker 原子保存当时每个 JSONL 记录的字节位置，重开界面时只恢复边界之后完成的问答，仍遵守历史恢复和保留策略。旧记录和 Agent 上下文照常保留。界面按预算淘汰消息时移除其后没有独立提问的回复，避免滚到顶部看到上一轮的孤立回答。失败时保留当前消息并显示错误。

## 统一掌机与 Rust 配置

- 掌机 App、`colibri --repl`、Rust CLI 和微信网关共用 Colibri 主目录中的 `config.toml`。共用 Rust 配置解析、模型工厂和会话核心。App 设置页是这份文件的编辑入口，语音和 MCP 配置也放进 TOML，掌机协议的字段列表只是界面投影。
- 首次运行在锁内迁移旧版实际保存过的 JSON 字段，保留掌机当前生效值。模型连接以同一来源成组迁移，避免把不同服务商的地址和密钥拼起来。已有 TOML 中其余字段、微信配置和注释保留。写入原子完成并保留旧文件供回退，迁移完成后应用不再从 JSON 加载配置。无应用模型配置的全新安装仍提示设置模型。
- 界面和模型、文件、记忆、工具运行逻辑保持分层。
- Esc 短按在松开时执行菜单切换或返回。按住 Esc 三秒则直接结束掌机应用，长按期间保持当前页面。按键自动重复不会触发短按；GUI 退出沿用原有运行时清理路径。
- 所有 Rust 应用入口统一为完全访问，包含掌机界面、两种 REPL、原生 CLI 和微信网关。读取现有 TOML 或使用应用默认配置时始终启用直接模式；旧 `tools.execution`、审批存档、文件根目录限制、Shell 拒绝列表与硬件写入授权位不参与执行判定。硬件协议能力、系统和服务凭据、功能开关及资源限额仍按各自规则处理。危险操作前的用户确认由系统提示词引导。
- 完全访问是 Rust 应用唯一的工具执行路径。删除共享会话与网关中的审批分流、审批等待和授权记录逻辑。工具输出直接报告运行状态，危险操作确认只存在于系统提示词中。
- 掌机保留 91px 聊天阅读区，发送者标签与正文分行。拼音候选显示于原底部提示栏。模型表单沿用字段列表，选中字段后查看和编辑。
- 聊天草稿单行显示，左右键按 UTF-8 字符移动光标，视窗跟随光标。键盘、拼音和语音草稿均插入光标处，退格删除光标前的字符。拼音组合时左右键仍用于候选翻页。未显示的草稿内容仍完整保留，发送时不含光标或省略标记。
- 聊天页 Page Up（Fn+L）和 Page Down（Fn+M）分别跳到第一条和最后一条可见消息。Home（Fn+K）和 End（Fn+N） 分别将草稿光标移到行首和行尾；输入视窗随光标移动。菜单和其它页面的导航维持现有行为。
- 网关状态在 Linux 优先读取内核的进程状态，僵尸或已死亡 PID 视为停止，允许重启覆盖旧状态。工具读取配置时在范围截取前遮盖凭据；共享 Rust 会话在工具结果进入模型和会话日志前遮盖已配置的凭据。工具继续使用当前系统账号，脱敏属于输出处理。
- Gateway 为每个收消息的通道运行同一套轮询恢复逻辑。适配器只返回成功事件或可重试、需认证、终止三类错误，并持有自己的游标。Gateway 对可重试错误执行 1 至 30 秒指数退避，成功后重置；一种通道停止时，其它已启动通道继续工作。状态命令按通道显示 connecting、online、reconnecting、auth_required 或 failed。微信长轮询失败时保留最近一次成功游标。验收使用假通道和模拟丢连接的 iLink 服务，覆盖恢复及认证失效。

### 掌机界面的标题与焦点

标题用粗体。标题、状态、录音计时及底部提示统一使用原主题强调色。菜单用左侧两像素标记配合选中底色，移动焦点时文字保持对齐。沿用 91px 阅读区和独立发送者行。两套主题共用布局。

录音启动后输入框显示“正在录音”和已用时间 / 一分钟上限。录音文字旁用五根圆角短线循环起伏，右侧计时每秒更新。短线表示录音状态，停止和取消时恢复原有输入显示。

消息标签使用已有粗体字体。相邻列表项及标题后的间距取 1px，普通段落前取 4px，段中标题前取 6px，首块贴齐。代码框左右各留 2px，折行计算使用相同宽度，引用及表格保留 6px。对照截图采用同一模拟器、主题和测试对话。

本轮界面调整以 0.1.40-m5stack1 部署到掌机。

## 整屏布局提案

以 320×170 的物理屏幕为准。标题、正文、输入和键帽共享 x=10 与 x=310 两条内容边线。背景统一使用深蓝绿，区域之间用一像素细线。圆角集中在键帽和当前选中项。浅色主题用相同的间距和线条层级。

| 区域 | 范围 | 展示规则 |
| --- | --- | --- |
| 顶栏 | y=0–22 | 左侧 14px 页名，蜂鸟保留。右侧为同一基线上的信号、时间、电量，统一使用中性色。 |
| 阅读区 | y=23–125 | 正文 12px，发送者独占一行。字号、正文边距和列表对齐一致。向上浏览时用细滚动指示标出当前位置。长代码保留浅底色。 |
| 输入和任务 | y=126–148 | 左侧草稿，右侧输入模式。录音时替换为声波和计时，转写和发送时替换为任务状态。无草稿时用短提示。 |
| 操作区 | y=149–169 | 两至三组当前有效操作，按键名画成小键帽。拼音候选出现时整行交给候选。 |
