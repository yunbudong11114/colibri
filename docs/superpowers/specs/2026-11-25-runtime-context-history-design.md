# 动态上下文快照与模型历史恢复

本轮仅修改设计和代码，按用户要求不编译、不测试、不打包、不部署。

## 动态快照

Memory和技能目录从每次请求重写的头部改为有序、不可变的上下文快照。快照放在对应用户消息之前，声明覆盖更早快照及摘要中的旧运行时事实。内容未变时不新增，变空时写清除快照。旧请求消息保持逐字一致。快照采用独立位置记录，不混入App聊天消息列表。

单条快照最多64KiB，累计快照超过256KiB时在模型请求边界压缩旧完整轮次并整合为最新快照。快照占用计入token估算及可选上下文内存预算。压缩改变前缀属于正常维护，保留近期工具调用完整组。

## 完整模型历史

保持现有load/load_after作为App展示历史路径，避免工具和内部快照出现在聊天面板。增加load_model供Agent恢复，返回消息、摘要及快照位置。原有纯文本历史加载接口保留给现有调用方。

每个AgentSession具有唯一model_stream。首次使用写model_seed，包含已有的恢复状态；用户消息保留model_text里的固定时间，助手事件新增完整tool_calls，工具结果保留完整model_text，运行时快照写runtime_context事件，压缩事件包含新的模型状态。日志追加写在进程间加锁，权限0600。

恢复按逻辑会话筛选，并选择最近活动model_stream，避免将并发或不同channel的工具消息拼到一起。恢复完整工具调用与结果，不执行恢复出来的工具；中断时缺失的结果补execution_unknown标记，要求先核实执行状态。旧日志未记录完整调用参数时仅恢复现有可用聊天文本，不能伪造工具执行记录。

恢复受现有扫描字节预算硬限制。消息数和字符数作为近期历史目标，最新完整轮次可超出软目标以保持工具配对，但不能超过扫描预算。超预算只移除完整旧轮次；单个轮次无法容纳时退回有界文本恢复。范围裁剪必然影响缓存复用，不能宣称任意长历史重启后100%命中。

CLI、REPL、Gateway和掌机采用相同模型恢复路径。Gateway使用实际session_key隔离，App聊天展示保持原路径。配置热重载保留动态快照；/clear只影响显示游标，/compact保留原有语义。网络模型能力缓存独立于本改动。

## 具体恢复协议

独立ModelHistory包含普通消息、摘要、ContextUpdate列表。模型请求按位置插入system-reminder用户消息；App展示仍使用现有纯文本load/load_after。每个模型请求边界重新读取已有缓存式Memory/技能目录，变化后追加快照。单轮内快照预算溢出且没有旧轮次可压缩时，仅整合快照并记录重定位事件，保留任务消息及完整工具组。

通过model_stream区分并发执行流；model_seed保存恢复起点，context_compact保存压缩后的完整近期状态。其余日志按用户/助手/工具事件增量重放，避免每次请求重复保存整份历史。源旧版本中没有完整tool_calls等字段时保留文本恢复路径，不伪造完整前缀。

恢复数量与字符数作为近期完整轮次选择目标，最新轮次可超过目标以保留完整工具组，但模型恢复状态受扫描字节预算硬限。超过硬限时丢弃整段旧轮次，无法容纳最新完整轮次则退回有界的展示文本历史。因预算而裁剪时不保证跨重启缓存前缀完整。Seed超过扫描预算时跳过写入，后续仍可从增量事件恢复有界近期任务。

超大工具结果的完整恢复字段同样有界：普通结果记录完整model_text，超出扫描预算可容纳的单事件大小时写明确的恢复截断标记及原有有界输出。恢复时保留调用/结果配对并标注“执行已结束但输出未完整保留”，避免误以为操作没有执行。默认展示日志读取规则保持不变。
